🦅 Horyon

Personal crypto-intelligence Telegram bot with semantic search, entity memory, and AI analyst views.

Python · PTB Next.js 14 pgvector OpenRouter

🧠 What This Is

A fully standalone personal crypto-intelligence platform. Ingests ~100 RSS feeds every 20 minutes into Postgres with pgvector embeddings. Two output modes:

📋

/digest

Curated 5–10 bullet summary of the last 24 hours. Auto-runs at 09:00 UTC+2 daily. Two-stage deduplication prevents repeat stories.

Daily
🔍

/updates <keyword>

ReAct agent with semantic feed search. Injects entity memory + analyst notes context. Free-text input also routed here.

On-demand

Intelligence Layer

  • Entity memory — self-building knowledge base: LLM extraction at ingest time, alias-match enrichment for prompts
  • Analyst scratchpad — post-digest theme & entity extraction stored in analyst_notes
  • Digest chain — last 3 daily digests injected as context into each new run
  • Pre-computed bullet analyses — up to 5 parallel LLM calls post-digest, stored in digest_bullet_analysis
  • Weekly macro digest — Monday 07:30 UTC; last 3 previous weeks injected for trend continuity

Deduplication (Daily Digest)

🔁
Stage 1 — URL pre-filter: feed items whose exact source URL appeared in the last 7 days are dropped before the LLM.
Stage 2 — Python post-filter: after LLM generation, bullets whose normalized title (first 6 significant words, lowercased, emoji-stripped) matches any title from the last 7 days are removed deterministically. The covered_bullets list is also injected into the prompt as an absolute exclusion list.

📥 Ingest Flow

── Ingest (every 20 min, only when inserted > 0) ── ingest.run_once() → insert_feed_items() → embed_missing() → entities.extract_and_upsert_entities(new_items) LLM call (max_tokens=600): texts → [{slug, name, type, aliases}] JSON → db.upsert_entity() → entity_memory (aliases union-merged, mention_count++)

Entity extraction only fires when inserted > 0 — no-op cycles skip the LLM call. The entity_memory table self-populates over time; warm-start available via seed_entities_from_protocols().

📰 Digest Flow

── Digest (daily 07:00 UTC + manual) ── digest.build_digest() ① entities.build_entity_context(feed_items) alias map from entity_memory → matched slugs (free, no LLM) → TVL + summary from defillama_protocols + entity_memory → "ENTITY CONTEXT" block (top ENTITY_CONTEXT_LIMIT entities) ② analyst.format_analyst_notes() → last ANALYST_NOTES_DAYS days of notes ③ analyst.format_digest_chain() → last DIGEST_CHAIN_DAYS past digests ④ build_digest_user(tweets, entity_context, digest_chain, analyst_notes, tvl_context) ⑤ llm.complete() → raw digest digest.run_digest() → build_digest() → persist_digest() → analyst.extract_and_persist(raw) ← non-blocking, logged on failure LLM call (max_tokens=800): digest → {notes: [...], entity_updates: {}} → analyst_notes row + entity_memory.summary updates per entity → generate_and_store_bullet_analyses(date, html) ← up to 5 parallel LLM calls → digest_bullet_analysis rows (title → analysis)
⚠️
Bullet analyses sync: db.delete_bullet_analyses(date) must be called before generate_and_store_bullet_analyses() on a date being regenerated — otherwise stale rows for old titles accumulate. The backfill handles this automatically.

🤖 Specialized Agent Flow

── Agent (per query) ── specialized.run_specialized(query) → entities.build_entity_context_for_query(query) → analyst.format_analyst_notes() → system = SPECIALIZED_SYSTEM + tvl_ctx + entity_ctx + notes_ctx → llm.run_agent(tools=[search_feed]) ReAct loop (capped at AGENT_MAX_STEPS=8) search_feed: pgvector ANN + ivfflat.probes (30-day window, top-K=40)
ℹ️
pgvector recall: db.search_feed() sets SET LOCAL ivfflat.probes. Without it, the 30-day filter returns ~1 result due to IVFFLAT's approximate nature.

📅 Weekly Macro Digest

── Weekly macro (Monday 07:30 UTC + manual) ── weekly.run_weekly() → coinmarketcap.get_market_data() (CoinGecko fallback if no CMC_API_KEY) → defillama: chain TVL + protocol TVL context → db: last 7d feed items (news context) → db: last 3 weekly_digest rows (trend continuity, dedup via WEEKLY_SYSTEM prompt) → llm.complete(WEEKLY_SYSTEM, user_prompt) → HTML content → db.upsert_weekly_digest(week_start, week_end, content, rotation) rotation = BTC | ETH | ALT | MIXED (detected from content) weekly_digest table → web layout.js → getWeeklyForDate(date) → Sidebar "Weekly" section: rotation badge + week range link → digest page: WeeklyMacro collapsible banner (above bullet list) → RightPanel WeeklyPanel: tabbed view (All/Market/Movers/DeFi/Trending/Stories/Watch) Key Stories links → /api/find-digest → matching daily digest date

WEEKLY_SYSTEM prompt instructs the LLM not to repeat Key Stories from previous weeks unless there's a concrete new outcome (confirmed amounts, governance result, etc.).

⚠️
DEX weekly volume — /overview/dexs?dataType=weeklyVolume returns HTTP 500 on the free DeFiLlama plan. This is expected and handled gracefully.

🏛 Governance Proposals

── Governance (every 30 min) ── snapshot.fetch_and_store() step 1 (cached 24 h): _graphql(_SPACES_QUERY) → all verified Snapshot spaces, top 500 by follower count → _spaces_cache (module-level, reset on container restart) step 2: _graphql(_PROPOSALS_QUERY, {spaces: _spaces_cache}) → active proposals (state="active"), first 50, ordered by end ASC → db.upsert_governance_proposals(rows) ON CONFLICT DO UPDATE governance_proposals table → web layout.js → getGovernanceProposals(limit=6) → Sidebar "Governance": green dot + space name + title + time remaining → links to snapshot.org/#/{space_id}/proposal/{proposal_id}

Closed proposals disappear automatically on the next upsert cycle — only state = 'active' proposals are stored. The verified spaces list is intentionally ephemeral (module-level cache, not in DB).

Layout Rules

  • BulletFeed.js owns all interaction state — do not add per-bullet state to BulletItem.js
  • Sidebar collapse: Sidebar.js sets data-sidebar on <html>; CSS responds. No ShellClient wrapper.
  • Mobile drawer: backdrop portalled into .shell (not document.body) — .shell { position:fixed } creates its own stacking context. Sidebar is z-index 102, backdrop is z-index 50 within shell.
  • cachedAnalysis prop is the primary path; /api/details is only the fallback for missing rows.

⚡ Conventions & Gotchas

Async + blocking
PTB is asyncio; all DB/LLM/Ollama calls are blocking. Always wrap in asyncio.to_thread() in handlers and cron jobs — never call blocking code directly from async context.
LLM returns tuples
llm.complete() and llm.run_agent() return (content, model_used). Always unpack both; callers record model_used to the DB.
Telegram HTML only
Prompts emit <b>/<a> only. Always pass output through telegram_html.sanitize(). Never send raw model output to Telegram.
pgvector recall
db.search_feed() sets SET LOCAL ivfflat.probes. Without it the 30-day filter returns ~1 result due to IVFFLAT's approximate nature.
chain_tvls filtering
defillama_protocols.chain_tvls includes internal keys like "Ethereum-borrowed". Frontend (RightPanel.js) filters out keys containing "-" or "borrowed" — keep this filter.
Caddy hot-apply
Caddyfile is bind-mounted by inode. Editing on host creates a new inode. Always use --force-recreate caddy.
app/ is baked into image
No volume mount on app/. After any Python change: docker compose build bot && docker compose up -d bot monitor.
Intelligence layer is additive
Entity extraction and analyst scratchpad both fail silently (logged WARNING), never breaking the digest. entity_memory self-populates from ingest; warm-start with seed_entities_from_protocols().
Dedup context & backfill
db.get_digest_contents_for_dedup(days, before_date=None) — the before_date param lets backfill look back from a specific date without reading future digests.
Bullet analyses sync
db.delete_bullet_analyses(date) must be called before regenerating — otherwise stale rows accumulate. Backfill handles this automatically.
OPENROUTER_API_KEY scope
Must be in docker-compose env for both bot AND web services. The web service uses it server-side only for /api/details.
Weekly dedup
WEEKLY_SYSTEM prompt instructs the LLM not to repeat Key Stories from previous weeks unless there's a concrete new outcome (confirmed amounts, governance result, etc.).
Mobile sidebar stacking context
.shell { position: fixed } creates a CSS stacking context. The backdrop must be portalled into .shell (not document.body) via createPortal — otherwise it renders above the sidebar. Uses position: absolute; z-index: 50 within shell (sidebar is z-index 102).
Snapshot verified spaces cache
Cached in a module-level variable for 24 h. Per-process — each container restart cold-fetches once. Do not make the spaces list configurable via DB; it's intentionally ephemeral.
No n8n
Fully standalone — migrated off n8n. Do not reintroduce n8n tables, containers, or coupling.

✅ Verifying Changes

  • /monitor — digest history, source health, TVL snapshot, entity/notes counts
  • docker compose logs -f bot — live output; check for errors after first ingest post-deploy
  • After Python changes — confirm first ingest cycle completes and entity extraction runs (look for entity extraction: N entities upserted)
  • For Telegram changes — inject a synthetic Update via process_update rather than testing against the live webhook
